# Patches to inspire_blur 0.4.1

Base: pub.dev `inspire_blur` 0.4.1, unmodified at tag `upstream-0.4.1`. See the full diff with `git diff upstream-0.4.1 -- packages/inspire_blur`. All numbers come from a 393x852 / 402x874 dpr-3 rig (macOS AOT and iOS Impeller) unless stated otherwise. The patches were first written against 0.4.0 and re-applied on 0.4.1. The only overlap was 0.4.1's OpenGL ES orientation guard in `inspire_blur_child.frag`, which is kept.

"Upstream?" is our view of whether a patch suits a PR to `inspirestack/inspire_blur` as it stands.

Not patched, but worth reporting upstream: **A.** `InspireBlurMode.auto` picks by Scrollable *ancestor*, so a blur that wraps a scroll view gets `imageFilter` on device and `animatedSampler` on web, two renderers that look different. **B.** The distribution map is generated by a synchronous `size x size` Dart loop on the UI thread in `didChangeDependencies` (about 408k iterations / 1.6 MB on an 852 pt phone, 13.9 ms on mount). A GPU gradient or an isolate would remove the first-touch stall. **C.** Backdrop blur returns an empty box on CanvasKit instead of the unblurred child.

---

## 1. imageFilter pass writes screen-relative deltas into the mask denominator

The shader computes `uv_blur = (xy + delta_lt) / (u_size + delta_lt + delta_rb)`. The animatedSampler pass passes `0.0` deltas; the imageFilter pass passes screen-relative ones. So the two passes put the same ramp in different places. **Fix:** zero them, matching the sampler pass.

## 2. `MAX_RADIUS 64` is logical px in one pass and device px in the other

`radius = ceil(3 * sigma)` is truncated to `MAX_RADIUS` and renormalised, not clamped, so overflow silently produces a chopped, box-like kernel. The animatedSampler pass divides sigma by dpr before the shader; the imageFilter pass doesn't. At dpr 3, a 14.67-logical sigma needs radius 132 under imageFilter and got 64, so rounded fills squared off. **Fix:** `MAX_RADIUS 192` (4.4x headroom at 2x and 3x). Upstream could instead normalise the unit across passes.

## 3. imageFilter pass doesn't clip the filtered child to its own box

`ui.ImageFilter.shader` reports the `ImageFilterLayer`'s **coverage** as `u_size`, and `FlutterFragCoord()` is relative to it. Coverage is whatever the subtree painted, so any descendant painting outside the box stretches and shifts the mask. Measured: 248.5 device px of coverage above the box, so the mask started at 0.37 instead of 1.0. `InspireChildBlur` already clips the whole pass to the same box, so adding the clip inside the pass is a visual no-op except for fixing the coordinates.

## 4. Band sampler: `Inspire.childBlurBand`

**Problem.** `AnimatedSampler` rasterises the whole child with `toImageSync` every frame and redraws it through the shader, even where the mask is 0 and the shader is a pass-through. Costs: (a) raster time; (b) 4.13% of below-zone pixels re-quantised (shimmer); (c) a full-child render target per frame, which is the memory problem below. Region selection isn't a parameter of `AnimatedSampler`'s layer, so it can't be fixed from outside.

**4a. Composition.** `InspireChildBlurBandSampler` collapses the two shader passes into one render object and one layer. It snapshots only `band + ceil(3*sigma) + 2` logical px, runs both passes over that window, and composites the real child directly everywhere else. The mask lookup stays exact because `delta_lt.y = windowTop` and `delta_rb.y = childH - windowTop - windowH`, so the denominator is still `childH`. The band and the child are a **partition** through the same `pushClipRect(..., Clip.hardEdge)` primitive. Two different primitives at one edge tie-break oppositely at half-pixel ancestor offsets and leave a dark row. An overlap is worse over a translucent child, because it composites to `2a - a^2`.
Measured: raster mean 2.40 to 1.23 ms, p95 8.80 to 4.05 ms, frames over 16.7 ms 1.7% to 0% (blur-off floor: 1.30 ms). Below-zone diff 76,620 px to 0.

**4b. Two anchors.** The band's direction is read from the mask (first and last non-zero rows), so the same widget handles a top header ramp and a bottom footer frost. A mask touching both edges falls back to the upstream composition.

**4c. One band picture per layer per frame.** `addToScene` ran once per *ancestor walk*, not per frame. A footer blur wrapping a header blur walked the inner layer twice: 6 window-sized targets per frame (about 13.5 MB/frame at 1206x467x4, 1.6 GB/s at 120 Hz). Same-frame walks now reuse the picture: 6 to 4.

**4d. Production budget.** `RenderRepaintBoundary.toImage` and similar out-of-band walks drive `addToScene` outside any frame, and `toImageSync` is rasterised asynchronously, so nothing throttles them. The drain signal is the **frame stamp advancing** (the pipeline is two deep, so a new stamp proves raster consumed one). At most 3 productions per layer per stamp; beyond that the layer re-serves its last picture for the *same geometry* (a geometry change always produces).

**4e. Bounded fallback sampler.** Every guard failure falls back to the upstream `AnimatedSampler` composition, which had no ceiling and whole-child targets (1206x2622x4 = 12.65 MB each). A healthy outer band around a guard-failed inner one, 120 out-of-band walks: **246 targets / 3.11 GB outstanding** before, 6 after. `InspireBoundedSampler` is `AnimatedSampler` with the same budget, same-frame reuse, and a `scene.dispose()` that `flutter_shaders` omits.

**4f. Global texture ledger.** A cap across frames: every `toImageSync` reports to `InspireTextureLedger`. Retirement is a 1x1 `Picture.toImage` echo posted after the productions on the FIFO raster runner. Past 32 outstanding (about 72 MB), same-geometry layers re-serve. The cap arms on the first completed echo and fails open before then. Stale keys compare **pixel-deciding values**, not closure identity, because callers rebuilding per scroll frame create fresh closures every frame. In production it acts as a backstop; once 4g landed it never fired.

**4g. Window-signature gate (the fix that mattered for the device kills).** The band hashes the content inside its window (picture identities plus container properties) and re-serves the last band while the hash is unchanged, with a forced refresh at least every 4th dirty frame because `PictureLayer.canvasBounds` is an estimate. Unknown layer types force a production, so new layer types can only cost performance, never correctness. A long animation elsewhere under the layer went from 1194 to 300 productions over 600 frames. Combined with a paint-only animation (`CustomPainter(repaint:)` instead of rebuilds): 1.25 to 0.50 productions per frame, equal to idle.

**4h. Passthrough at sigma 0.** Previously the builder returned the bare child at sigma 0 and the sampler stack above it otherwise. That type change reparented the caller's subtree on every crossing (60 of 60 rows rebuilt on two gesture frames). Now the same widgets stay mounted and the layer composites like a plain `OffsetLayer`.

**4i. Smaller intermediates, filter-aware gate, band backgrounds.** The vertical pass's intermediate holds only band rows (about 12% fewer pixels). The gate hashes `BackdropFilterLayer`/`ImageFilterLayer`/`ColorFilterLayer` by value when `dart:ui` equality covers every pixel input. `InspireBandBackground(exemptFrom:)` lets an animated background behind the content be hashed by offset only, as a caller-owned look decision.

**4j. Tight window.** The kernel radius is per fragment (`ceil(3*sigma*mask)`), and the mask is about 0 at the band's foot, so the window now ends at the furthest row any fragment actually reads: 138 to 11 extra device rows, 1.356 to 1.206 MP per production, byte-identical output.

## 5. Kernel sampling modes

Under the sampler passes a texel is one **logical** px (3 device px at dpr 3), so at low sigma the kernel averages a few copies of the content 3 device px apart, giving a stepped, ghosted look ("pixelated header" on a short list bounced at low scroll progress). `InspireBlurConfig.sampling` (`unit` default = upstream loop unchanged; `fineStep`, `denseTaps`, `minSigma`) reaches the shader as two extra floats.

## 6. `realUnderlap`

The band sampler draws the real child only on its side of the seam. A `BackdropFilter` inside the body straddling the seam samples nothing above it and goes dark (15/255 vs 52). `realUnderlap` lets the real child extend under the opaque band picture. This is only safe over opaque content. Default 0 keeps the half-open partition unchanged.

## 7. `MediaQuery` aspects

`InspireBlurWrapper` read `MediaQuery.of(context).size.longestSide` and both passes read `MediaQuery.of(context).devicePixelRatio`. So every keyboard animation frame (about 15 per open) rebuilt every blur subtree. Now uses `MediaQuery.sizeOf` and `devicePixelRatioOf`: same values, no keyboard dependency.
